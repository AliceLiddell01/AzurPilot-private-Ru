# Сравнительный benchmark английских OCR-моделей

Персональная версия AzurPilot поддерживает только международный сервер
**EN/Global**. Китайские, японские и традиционно-китайские OCR-веса удалены из
поставки, а соответствующие настройки скрыты из WebUI.

Историческое логическое имя `cnocr` сохранено ради совместимости нескольких
игровых модулей, но в персональном форке оно направляется на английскую модель
`azur_lane` и не загружает китайские веса. Такое сопоставление работает как с
ONNX Runtime, так и с NCNN.

## Что сравнивается

Benchmark последовательно запускает все установленные английские варианты:

- `alocr_en_900k`;
- `azur_lane_v6_6`;
- `azur_lane_v6_5`;
- `ppocr_v6`;
- `alocr_en_v2_6`;
- `alocr_en_v2_0`;
- `alocr_en_v1_0`;
- отдельную английскую модель `ncnn_azur_lane`, если установлены NCNN-веса.

`auto` не является отдельной моделью. Это настройка, которая выбирает одну из
перечисленных версий по умолчанию.

## Один и тот же набор данных

Все модели получают один и тот же набор `module/daemon/sets_num.*` и один и тот
же список ожидаемых строк из `val.txt`. Поэтому результаты внутри таблицы можно
сравнивать между собой.

Старые наборы `sets_azur_lane_jp` и `sets_zhcn` удалены вместе с
неиспользуемыми языковыми моделями.

Тест проверяет **распознавание готовых текстовых кропов**. Он не измеряет:

- поиск текста на полном экране;
- качество детектора `PP-OCRv6_tiny_det`;
- поведение на анимациях и переходных кадрах;
- реальные игровые сценарии вне набора `sets_num`.

## Зависимость от Stage 8B

В открытом Stage 8B PR находится production-нормализация ложных пробелов рядом
с числовыми разделителями. Benchmark использует эту же функцию, когда она
доступна, чтобы сравнивать модели по фактическому пользовательскому результату,
а не по промежуточной сырой строке движка.

До синхронизации ветки с итоговым Stage 8B запуск считается предварительным.
Финальный Windows/DirectML/NCNN benchmark выполняется только после объединения
обоих изменений на одном exact head SHA.

## Запуск

```powershell
uv run python -m dev_tools.ocr_english_model_benchmark --profile alas
```

Для временного выбора устройства ONNX-моделей:

```powershell
uv run python -m dev_tools.ocr_english_model_benchmark --profile alas --device gpu
```

Постоянная конфигурация профиля не изменяется.

## Вывод

Для каждой модели показываются:

- конкретная версия;
- backend;
- фактически созданный runtime/provider;
- имя файла весов;
- точность и количество ошибок;
- среднее время распознавания;
- p95 задержки;
- итоговый статус;
- место в рейтинге.

Рейтинг сначала учитывает точность. Более быстрая модель с ошибками не может
обойти модель с точностью 100%. При равной точности используются p95, средняя
задержка и время загрузки.

Полный машинно-читаемый результат сохраняется в:

```text
artifacts/ocr/english-model-benchmark.json
```

Отчёт и распакованный временный набор не добавляются в Git.

## Значение статусов

- `ИДЕАЛЬНО` — 100% на текущем наборе;
- `ХОРОШО` — от 99% до 100%;
- `РИСК` — от 95% до 99%;
- `НЕ ПОДХОДИТ` — ниже 95%;
- `НЕ УСТАНОВЛЕНА` — отсутствуют веса или словарь;
- `ОШИБКА` — модель не удалось загрузить или выполнить.

Статус относится только к текущему набору `sets_num` и не является абсолютной
оценкой модели на всех экранах игры.

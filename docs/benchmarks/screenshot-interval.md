# Benchmark интервалов снимков экрана

Инструмент подбирает значения для двух параметров профиля:

- `Optimization_ScreenshotInterval` — обычный режим, допустимо `0.001–0.3` с;
- `Optimization_CombatScreenshotInterval` — бой, допустимо `0.001–1.0` с.

Benchmark не изменяет профиль автоматически. Он временно задаёт интервалы только внутри текущего процесса, делает снимки через настроенный backend и записывает матрицу измерений и рекомендации в JSON/Markdown.

## Что измеряется

Для каждого кандидата сохраняются:

- фактический FPS;
- интервалы между началами соседних снимков: `p50`, `p95`, максимум;
- доля кадров, которые не уложились в целевой интервал с допуском;
- CPU текущего Python-процесса;
- общая загрузка CPU системы;
- изменение RSS процесса;
- контракт кадра `numpy.ndarray` BGR;
- ошибка конкретного кандидата, если она возникла.

Значение считается устойчивым, когда получено не менее пяти кадров, достигнуто не менее 90% целевого FPS, доля пропусков не превышает 10%, а `p95` укладывается в интервал с допуском `10% + 2 мс`.

## Запуск

Из корня репозитория:

```powershell
uv run python -m dev_tools.screenshot_interval_benchmark `
    --profile alas `
    --serial-from-config `
    --expected-head <EXACT_HEAD_SHA>
```

Сначала инструмент попросит открыть типичный обычный экран и ввести `NORMAL`. После первой матрицы нужно открыть бой с активной анимацией и ввести `COMBAT`.

Для проверки обоих режимов на одном и том же экране:

```powershell
uv run python -m dev_tools.screenshot_interval_benchmark `
    --profile alas `
    --serial-from-config `
    --expected-head <EXACT_HEAD_SHA> `
    --same-screen
```

Параметры:

- `--duration 2.0` — длительность измерения каждого кандидата, `0.5–30` с;
- `--warmup-frames 2` — число прогревочных снимков перед измерением;
- `--normal-intervals "0.01,0.025,0.05,0.1,0.2,0.3"` — собственная сетка обычного режима;
- `--combat-intervals "0.05,0.1,0.2,0.3,0.5,1.0"` — собственная сетка боя;
- `--report` и `--markdown-report` — пути выходных файлов;
- `--non-interactive` — запуск без подтверждений; контекст боевого экрана в отчёте будет помечен как непроверенный.

## Результаты

По умолчанию создаются:

```text
artifacts/device/screenshot-interval-benchmark.json
artifacts/device/screenshot-interval-benchmark.md
```

Для backend, где интервалы действительно настраиваются, отчёт содержит четыре профиля:

- `fast` — минимальные устойчивые интервалы;
- `balanced` — рекомендуемый компромисс с запасом к `p95`;
- `low_load` — приоритет снижения нагрузки;
- `current` — исходные значения профиля.

Основной рекомендацией считается `balanced`. Это эвристика, а не автоматическая запись настроек: перед изменением профиля следует проверить таблицу, особенно `p95`, пропуски и общую загрузку системы.

Для `scrcpy` production-код принудительно использует `0.1` с для **любого** значения обеих настроек. Поэтому benchmark выполняет по одному измерению на обычном экране и в бою и возвращает профиль `backend_forced` со значениями `0.1/0.1`, а не создаёт фиктивную матрицу кандидатов.

## Ограничения

- Результат относится только к exact head, выбранному профилю, backend и текущему состоянию компьютера.
- CPU текущего Python-процесса не включает всю нагрузку эмулятора и внешних ADB-процессов, поэтому рядом сохраняется общая загрузка системы.
- Для `ADB`/PNG динамичный бой может быть тяжелее статического экрана из-за различий в сжатии; поэтому режимы измеряются отдельно.
- `scrcpy` получает видеопоток непрерывно; изменение двух параметров не меняет частоту самого видеопотока и не обходит принудительный интервал `0.1` с.

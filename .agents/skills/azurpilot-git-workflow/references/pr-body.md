# Описание PR

Пиши для человека, не читавшего чат. Заголовок и обычный текст — на русском;
имена API, CLI, файлов, классов, коды причин и названия заданий CI сохраняются.
Описание составляет агент по фактам, без схемы или формирователя Python и без
квот на число символов. Небольшой PR короче архитектурной миграции.

Содержательные разделы:

- `Цель`: проблема, причина и итоговое поведение; обычно 1–3 предложения.
- `Область изменений`: границы, подсистемы, репозиторий, base branch и точный
  SHA базы, ветка задачи и HEAD. Исторический снимок не заменяет базу.
- `Реализация`: существенные решения и причины, при необходимости пример до/после.
- `Проверки`: фактически выполненные проверки и результаты, честные пропуски.
- `CI`: точный HEAD, обязательные задания, конечное или ожидаемое состояние.
- `Безопасность / проверка секретов`: реальный сканер, проверка индекса и
  точного диапазона коммитов; остальные применимые проверки безопасности.
- `Внешняя проверка`: независимые проверки и обоснованная обработка замечаний.
  Незапрошенный CodeRabbit — `NOT_RUN`.
- `Готовность`: реализация, обязательные проверки, пользовательское ревью,
  отдельное разрешение слияния и предполагаемый способ merge.
- `Миграция / откат`: совместимость, смена операторских команд и восстановление.
- `Ограничения`: реальные недоступные проверки, риски и препятствия либо их отсутствие.

Обычно достаточно короткого абзаца или 2–6 содержательных пунктов на раздел.
Это ориентир, не квота. Не вставляй полный журнал команд, повторы свидетельств
или текст ради объёма. Неприменимость раздела укажи кратко, факты не выдумывай.
При изменении фактов сначала отредактируй локальный `.md`, перечитай его,
выполни `gh pr edit --body-file <file>` и сравни полное повторное чтение.

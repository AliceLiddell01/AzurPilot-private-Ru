# Инженерный контракт

Этот reference дополняет `AGENTS.md` и `.codex/context/GIT-WORKFLOW.md`; он не
заменяет их.

## Изменяемость и источники истины

Task-specific hardcode запрещён. Значения, которые меняются вместе с задачей,
ивентом, картой, магазином, OCR-сценарием, task ID, migration phase, smoke-run,
PR или историческим состоянием, должны приходить из подходящего config, registry,
model, abstraction, extension point, schema, data-driven mapping или generated
source. Литерал допустим только как стабильная часть внешнего протокола/domain
contract, уже установленная архитектурная константа текущего scope или прямо
заданный пользователем узкий контракт. Исключение должно быть минимальным и
объяснимым.

Источники истины читаются в таком порядке: фактический код и конфигурация,
исполняемые тесты/generated contracts и подтверждённое поведение, canonical
docs и Wiki форка, `.codex/context/`, затем upstream и внешняя документация.
При расхождении документации с кодом сначала устанавливай фактическое поведение.

## Устойчивые tests и CI

Permanent CI и tests проверяют текущее продуктовое поведение. Не добавляй
проверки, fixtures, baselines, SHA, evidence или jobs, существующие только ради
номера этапа разработки, временной migration phase или конкретного PR. Если
задача имеет внутреннее название этапа, имя и ожидания теста должны описывать
реальное поведение.

Не меняй исправный CI ради workflow. Публичный required contract проекта —
`Python`, `Windows`, `Security`; подробности и локальные эквиваленты находятся в
`docs/ci.md`. Не добавляй `paths`-фильтры или обходы, которые могут оставить
required context в состоянии `Expected`.

## Русский текст затронутого файла

Если файл попал в diff, аудируй весь этот файл. Комментарии разработчика,
operator-facing логи и новые diagnostic messages должны быть литературным
русским; существующий китайский или английский человеческий текст в том же
затронутом файле переводи как связную часть scope. Не переводи API names,
идентификаторы, protocol tokens, exact external error codes, package names,
paths, URLs, технические термины и собственные имена, когда их требует контракт.
Не запускай глобальную русификацию нетронутых файлов.

## Checkout и безопасность

Последовательная разработка выполняется в текущем основном checkout. Отдельный
WSL2 Arch checkout предназначен только для независимого CodeRabbit review и не
должен получать пользовательские secrets/config. Не смешивай product changes с
review checkout и возвращай подтверждённые fixes в основной checkout.

Не используй destructive Git-операции, не отменяй unrelated changes и не
публикуй секреты, cookies, device identifiers, dumps или локальные конфигурации.

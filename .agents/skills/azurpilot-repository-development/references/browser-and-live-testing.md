# Browser и live acceptance

Используй этот reference только если изменение действительно требует GUI,
WebUI, браузера, устройства, эмулятора, игры или runtime smoke.

## Браузер и WebUI

- Используй доступный встроенный Browser/Computer Use Codex desktop; если
  текущая поверхность его не предоставляет, сначала фактически проверь
  доступные интеграции и не выдумывай capability.
- Для локального WebUI сам запусти repository-defined dev/runtime server,
  открой страницу и проверь rendered state. Для диагностики добавляй
  screenshot, DOM или CDP evidence только когда это действительно надёжно.
- Применяй bounded waits и bounded retry/reload. Один хрупкий selector чужого
  SPA не является доказательством пользовательского состояния.
- После fix повтори тот же rendered-state gate. Не перекладывай обычные клики и
  проверки на пользователя, если Codex может выполнить их сам.

## Устройство и игра

Используй существующие typed tools, project runner и Universal Smoke Harness.
Соблюдай цикл «снимок → распознавание → одно допустимое действие → новый
снимок». Не подменяй Harness цепочкой случайных shell-команд, ручных кликов,
искусственных `sleep` или бесконечных retry. Unknown, incomplete или
недостаточное evidence оставляй fail-closed; не превращай отсутствие acceptance
в PASS.

Не выполняй irreversible gameplay, покупки, расход ресурсов или действия в
пользовательской среде без отдельного безопасного основания. Собирай только
санитизированные evidence и после теста очищай принадлежащие задаче процессы,
sessions и временные профили.

Если для объективно обязательного gate нужен секрет, CAPTCHA, физическое
действие или недоступная foreground capability, укажи один точный внешний шаг,
ожидаемый результат и evidence при ошибке. Это исключение не превращает
пользователя в ручного CI.

# Решение проблем

Эта страница — первая точка входа, когда AzurPilotRu работает не так, как ожидается.

Главное правило: **сначала определить слой проблемы, затем исправлять его**. Не удаляйте `.venv`, Docker volumes, config или Git history наугад.

## Начните с Doctor

```powershell
azur doctor
```

Doctor проверяет repository, Git, Python, uv, окружение, runtime, CLI/PATH, ADB, Docker, Redis и другие фундаментальные возможности.

### Если нужна расширенная проверка интеграций

```powershell
azur doctor --full
```

## Команда azur не найдена

Если Build только что завершился:

1. закройте PowerShell;
2. откройте новое окно;
3. повторите `azur doctor`.

Старое окно не получает новый пользовательский PATH автоматически.

Если Build не завершился, запускайте doctor через bootstrap-команду из корня checkout.

## WebUI не запускается

Проверьте:

- существует ли `config/deploy.yaml`;
- готова ли `.venv`;
- работает ли Docker Desktop;
- свободен ли порт `25548`;
- не остался ли неподтверждённый lifecycle state.

Используйте:

```powershell
azur doctor
azur start
```

Если Start сообщает о чужом процессе на порту, не завершайте его автоматически.

## WebUI запущен, но страница не открывается

Стандартный адрес:

```text
http://127.0.0.1:25548/
```

Если в deploy-конфигурации порт изменён, используйте фактическое значение.

Закрытие браузера не останавливает backend.

## Docker недоступен

Doctor может сообщить:

- Docker CLI не найден;
- Compose не готов;
- canonical `.env` или compose file недоступны;
- PostgreSQL/Redis не прошли health.

На Windows убедитесь, что Docker Desktop полностью запущен, а не только присутствует в системе.

## PostgreSQL недоступен

Не создавайте второй случайный PostgreSQL рядом с проектом.

Штатный Start владеет Docker Compose lifecycle PostgreSQL/Redis и выполняет bootstrap/prepare через каноническую инфраструктуру.

Сначала исправьте Docker/.env и повторите Doctor/Start.

## Redis недоступен

Redis — runtime cache. Его отсутствие может блокировать поддерживаемую инфраструктуру, но не означает потерю durable данных PostgreSQL.

Исправляйте canonical Compose instance, а не подключайте произвольный Redis на том же порту.

## ADB не настроен

На Windows Build должен подготовить проектный ADB.

Если Doctor показывает `ADB не настроен`:

1. убедитесь, что Build завершился;
2. не подменяйте ADB случайным бинарником;
3. проверьте MuMu;
4. проверьте serial;
5. повторите `azur doctor`.

## Устройство не найдено

Если `Serial: auto` и запущено несколько эмуляторов, автообнаружение может быть неоднозначным.

Укажите конкретный serial в профиле.

Проверьте, что Azur Lane Global запущена именно на этом устройстве.

## Игра не распознаётся

Поддерживается только:

```text
com.YoStarEN.AzurLane
server: en
```

CN/JP/TW package не должны автоматически подменяться на Global.

## Задача не запускается

Проверьте:

- `Scheduler.Enable`;
- `NextRun`;
- активную текущую задачу;
- приоритеты;
- stop conditions;
- игровые таймеры;
- наличие ручного takeover/error.

Комиссия, Research и Reward имеют особое always-enabled scheduler-поведение.

## Задача делает не то

Сразу остановите runtime:

```powershell
azur stop
```

Затем проверьте:

- выбранный профиль;
- serial;
- Campaign.Name;
- флоты;
- подлодки;
- stop conditions;
- параметры конкретной задачи.

Не пытайтесь «перебить» ошибочную задачу включением других scheduler-задач.

## Повреждено окружение

Сначала:

```powershell
azur repair --diagnostic-only
```

Если диагностика подтверждает проблему окружения:

```powershell
azur repair
```

Repair не предназначен для исправления Git, PostgreSQL или игровых настроек.

## Update не проходит

Update требует:

- остановленный WebUI;
- подтверждённый Git remote;
- безопасный fast-forward;
- рабочий текущий Python;
- возможность подготовить candidate dependencies;
- PostgreSQL backup;
- подтверждённые postconditions.

Не используйте `git reset --hard` как универсальное лечение ошибки Update.

## Какие данные собрать

Для дальнейшей диагностики сохраните:

- вывод Doctor;
- точную команду;
- имя профиля;
- имя задачи;
- последние сообщения WebUI/консоли;
- screenshot игрового состояния при необходимости.

Перед публикацией удалите секреты.

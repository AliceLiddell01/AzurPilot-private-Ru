# Запуск и остановка

Повседневный lifecycle AzurPilotRu управляется командами `azur start` и `azur stop`.

Они намеренно отделены от Build, Repair и Update: обычный запуск не должен скрыто менять исходный код или пересобирать всё окружение.

## Запуск

Обычная команда:

```powershell
azur start
```

Открыть браузер после подтверждения готовности:

```powershell
azur start --browser
```

По умолчанию Start имеет общий timeout 60 секунд. Его можно изменить параметром `--timeout`.

## Что проверяет Start

Перед созданием WebUI Start проверяет:

- что checkout подготовлен;
- что существует `gui.py`;
- что существует `config/deploy.yaml`;
- что проектный Python доступен;
- что инфраструктура PostgreSQL/Redis готова;
- что порт WebUI можно безопасно идентифицировать;
- что на порту нет чужого процесса;
- что новый WebUI действительно достиг состояния readiness.

Start не должен завершать чужой процесс только потому, что тот слушает порт `25548`.

## Повторный Start

Если уже запущен подтверждённый процесс AzurPilotRu, команда проверяет его состояние.

Если WebUI отвечает, результат считается готовым. Если процесс существует, но readiness ещё не подтверждён, состояние может быть показано как running, а не ready.

Это безопаснее, чем запускать второй экземпляр поверх первого.

## Foreground

Для диагностики доступен:

```powershell
azur start --foreground
```

В этом режиме CLI удерживается до завершения WebUI.

Обычному пользователю для постоянной работы foreground не требуется.

## Остановка

Штатная команда:

```powershell
azur stop
```

Stop завершает только дерево процессов, чья идентичность подтверждена как принадлежащая текущему AzurPilotRu.

Если на том же порту работает чужой процесс, Stop не должен считать его своим.

## Закрытие браузера

Закрытие вкладки WebUI **не равно остановке AzurPilotRu**.

Браузер — только клиент интерфейса. Backend продолжает работать, пока его не остановит `azur stop`, foreground lifecycle или штатное завершение процесса.

## Когда обязательно остановить WebUI

Перед `azur update` и полноценным `azur repair` runtime должен быть остановлен.

Если операция сообщает, что WebUI всё ещё активен или порт занят, сначала разберитесь с lifecycle, а не обходите проверку вручную.

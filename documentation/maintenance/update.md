# Обновление

Обновление пользовательской установки выполняется отдельной командой:

```powershell
azur update
```

Обычный `azur start` не выполняет скрытое Git-обновление.

## Требование: WebUI должен быть остановлен

Перед Update выполните:

```powershell
azur stop
azur update
```

Update проверяет не только lifecycle record, но и фактическое состояние порта WebUI. Если нельзя доказать, что runtime остановлен, обновление прекращается.

## Как обновляется Git

Update намеренно не использует destructive-команды вроде:

- `git reset --hard`;
- `git clean`;
- `git pull`;
- `git rebase`;
- force push.

Разрешённая модель обновления — проверенный fast-forward.

Это означает, что локальная история не должна молча переписываться ради получения новой версии.

## Проверка репозитория

Перед изменением Update проверяет:

- текущую ветку;
- remote;
- ожидаемый remote branch;
- каноническую идентичность repository URL;
- отсутствие конфликтующей Git-операции;
- возможность безопасного fast-forward.

Параметры можно переопределять CLI-флагами, но обычной пользовательской установке это не требуется.

## Зависимости

До применения обновления сервис проверяет кандидат `pyproject.toml` + `uv.lock` и подготавливает кандидатное окружение.

Это позволяет остановить Update до переключения рабочего состояния, если новые зависимости нельзя подготовить.

## PostgreSQL backup

Update создаёт логическую резервную копию PostgreSQL в формате custom (`pg_dump -Fc`) и проверяет её.

Резервная копия должна находиться **вне изменяемого checkout**. Если корректный backup создать нельзя, Git-изменения не должны продолжаться.

## После обновления

После применения новой версии Update проверяет постусловия, включая состояние окружения и обязательную MCP reconciliation, если для текущего проекта она требуется.

Если effective MCP session требует reload, Update не маскирует это как полностью успешное постусловие.

## Локальные изменения

Update не предназначен для уничтожения пользовательских изменений.

Если Git-состояние не позволяет безопасный fast-forward, исправьте его осознанно: commit/stash/revert должны быть вашим решением, а не скрытым действием updater.

## После успешного Update

Запустите:

```powershell
azur doctor
azur start --browser
```

Если Update был прерван или сообщил о recovery state, не повторяйте его бесконечно. Сначала используйте [Диагностику и восстановление](diagnostics-repair.md).

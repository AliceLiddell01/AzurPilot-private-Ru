# Данные и резервные копии

AzurPilotRu хранит несколько разных классов данных. Резервная копия «всей папки проекта» не всегда является правильным способом сохранить пользовательское состояние.

## Профили

Пользовательские профили находятся в `config/*.json` и содержат настройки задач, устройства и планировщика.

Для ручной копии профиля:

1. остановите AzurPilotRu;
2. определите нужный JSON;
3. скопируйте его в безопасное место;
4. не публикуйте копию без проверки sensitive-полей.

## deploy-конфигурация

`config/deploy.yaml` описывает операционные параметры установки: пути, WebUI, Git identity и другие значения.

Это не игровой профиль.

Повреждение или удаление deploy-конфигурации может сделать lifecycle-команды неготовыми, поэтому не смешивайте его с импортом/экспортом игровых профилей.

## PostgreSQL

PostgreSQL — постоянное хранилище данных текущей архитектуры.

Во время `azur update` создаётся проверенная логическая резервная копия через `pg_dump -Fc`.

Backup:

- создаётся вне изменяемого checkout;
- проверяется на существование и минимальный размер;
- получает SHA-256;
- сопровождается provenance metadata.

Если PostgreSQL backup не удалось подтвердить, Update должен остановиться до Git-изменений.

## Где находится PostgreSQL backup

Путь может быть настроен через `PostgreSqlBackupRoot`.

Если пользовательский путь не задан, tooling использует свой внешний state layout для PostgreSQL backups.

Ключевое требование: каталог не должен находиться внутри checkout репозитория.

## Redis

Redis в текущей архитектуре — восстанавливаемый runtime cache, а не замена постоянным данным PostgreSQL.

Поэтому не следует делать «backup Redis» и считать этим сохранённым всё состояние AzurPilotRu.

## .venv

`.venv` — воспроизводимое окружение программы, а не пользовательская резервная копия.

Build/Repair/Update умеют пересоздавать или транзакционно заменять окружение. Копирование `.venv` на другой компьютер не является поддерживаемым способом миграции установки.

## .env

Локальный `.env` используется Docker-инфраструктурой и может содержать credentials.

Его нельзя прикладывать к issue или хранить в публичном репозитории.

Если вы делаете личный disaster-recovery backup, храните `.env` как секрет.

## Что сохранять для переноса установки

Минимально разумный набор зависит от цели:

- игровые настройки → пользовательские профили;
- операционная конфигурация → `config/deploy.yaml`;
- durable данные → PostgreSQL backup;
- секреты инфраструктуры → защищённая копия `.env`.

Перед восстановлением на другой машине сначала разверните чистое приложение, а затем возвращайте данные по слоям.

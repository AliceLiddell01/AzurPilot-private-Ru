# Разработка AzurPilotRu

Этот раздел предназначен для человека, который хочет **изменять сам проект**, а не только пользоваться автоматизацией.

Он не требует читать внутренний agent context и не дублирует `.codex/context/`. Здесь описан человеческий путь: как устроен репозиторий, как подготовить среду, где находятся основные подсистемы, какие проверки запускать и как оформлять изменение.

## С чего начать

Перед первым изменением:

1. прочитайте [Среда разработки](environment.md);
2. посмотрите [Основные подсистемы](subsystems.md);
3. убедитесь, что проект собирается и тесты запускаются;
4. создайте отдельную рабочую ветку от актуального `personal/stable`;
5. меняйте только тот слой, который относится к задаче;
6. обновляйте тесты и документацию вместе с поведением.

## Главные ветки

В репозитории есть две принципиально разные постоянные ветки:

- `master` — чистое зеркало upstream;
- `personal/stable` — стабильная пользовательская версия AzurPilotRu.

Обычная разработка **не ведётся напрямую в `personal/stable`**. Изменения попадают туда через Pull Request и проверки.

`master` также нельзя использовать для fork-only функциональности: он должен оставаться зеркалом исходного проекта.

## Источники истины

При разработке важно отличать source-файлы от производных.

Например, configuration pipeline начинается с YAML-источников и генерирует:

- `module/config/argument/args.json`;
- `module/config/argument/menu.json`;
- `module/config/config_generated.py`;
- `config/template.json`;
- части i18n.

Не исправляйте generated-файл вручную, если изменение принадлежит source YAML или generator.

## Что считать готовым изменением

Минимально изменение должно:

- решать заявленную задачу без случайного расширения scope;
- иметь релевантные тесты;
- сохранять Global/EN и русскоязычный runtime-контракт;
- не добавлять секреты;
- не оставлять generated drift;
- обновлять пользовательскую документацию, если меняется observable behavior;
- проходить required CI на точном head PR.

## CI

Главный PR workflow — `.github/workflows/ci.yml`.

Required contexts для `personal/stable`:

- **Python**;
- **Windows**;
- **Security**.

Дополнительно выполняется `macOS core tooling`, но он не входит в текущий required ruleset.

Подробнее: [Тестирование](testing.md) и [Git и Pull Request](git-pr.md).

# Порт

Раздел **«Порт»** содержит общие настройки AzurPilotRu, а не отдельный игровой режим.

В текущем task contract сюда входят:

- **Настройки AzurPilot**;
- **Общие настройки**;
- **Настройки перезапуска**;
- **Автосканирование флотов**.

## Настройки AzurPilot

Здесь находятся базовые группы приложения:

- `Emulator` — подключение к Android runtime;
- `EmulatorInfo` — тип и параметры эмулятора;
- `Error` — обработка ошибок и внешние уведомления;
- `Optimization` — OCR, интервалы снимков и поведение ожидания;
- `DropRecord` — запись отдельных игровых результатов;
- управление эмулятором.

Это параметры всего профиля, поэтому ошибка здесь влияет сразу на несколько задач.

## Общие настройки

Сюда входят:

- журналирование;
- отставка кораблей;
- one-click retire;
- усиление;
- общий контроль настроения;
- приоритеты планировщика.

Приоритеты планировщика — продвинутая настройка. Не меняйте их только ради того, чтобы «заставить задачу запуститься раньше»: это может изменить порядок зависимых задач по всему профилю.

## Перезапуск

Задача Restart имеет собственный `Scheduler` и параметры перезапуска.

Текущая локализация описывает:

- случайную задержку после времени обновления сервера;
- необязательную очистку кэша Android-приложения после принудительного завершения клиента.

Очистку кэша не следует включать без конкретной необходимости.

## Автосканирование флотов

`FleetAutoScan` — плановая запись состава выбранных флотов в историю.

У неё есть обычные scheduler-параметры, включая:

- Enable;
- PushNotification;
- NextRun.

Эта задача полезна как источник актуальной информации о составе флотов для связанных функций, но её расписание не должно подменять ручную проверку флота перед новой боевой конфигурацией.

## Что проверить новичку

В разделе «Порт» в первую очередь проверьте:

1. serial устройства;
2. package Global;
3. методы снимка и управления;
4. обработку ошибок;
5. внешние уведомления;
6. поведение при длительном ожидании;
7. только после этого — дополнительные автоматические действия.

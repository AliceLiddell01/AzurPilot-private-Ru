# Профили и конфигурация

Профиль AzurPilotRu — именованный набор настроек для конкретного пользовательского сценария. Он связывает настройки устройства, задачи, планировщик и сохранённые параметры автоматизации.

## Где находятся профили

Обычные профили хранятся как JSON-файлы непосредственно в каталоге:

```text
config/
```

Имя файла соответствует имени профиля:

```text
config/alice.json
→ профиль alice
```

Шаблонные файлы с именами, начинающимися на `template`, не считаются пользовательскими профилями.

## Что считается корректным профилем

AzurPilotRu проверяет структуру файла. Для обычного профиля ожидаются как минимум:

- объект `Alas`;
- группа `Alas.Emulator`;
- объект `General`;
- scheduler-группа хотя бы у одной задачи.

Поэтому не каждый `*.json` в `config/` автоматически становится профилем.

Также discovery ограничивает размер и количество файлов, отклоняет symlink/junction-кандидаты и коллизии имён без учёта регистра. Это сделано для того, чтобы WebUI и runtime не принимали неоднозначный файл за реальную пользовательскую конфигурацию.

## Один профиль — один самостоятельный набор настроек

Разные профили могут использовать:

- разные Android serial;
- разные включённые задачи;
- разные расписания;
- разные флоты;
- разные ограничения;
- разные параметры уведомлений.

Поэтому перед изменением настроек всегда проверяйте, **какой профиль открыт**.

## Не редактируйте runtime-состояние как обычную настройку

В конфигурации встречаются служебные значения вроде:

- `NextRun`;
- сохранённых счётчиков;
- записанного времени;
- storage/runtime-состояния.

Часть из них обновляется самим приложением. Ручная правка такого значения может изменить работу планировщика или нарушить ожидаемое состояние.

Для обычной эксплуатации используйте WebUI, а прямое редактирование JSON оставляйте для осознанной диагностики и резервного восстановления.

## Резервная копия профиля

Перед крупной перенастройкой можно сохранить копию соответствующего JSON-файла профиля, пока AzurPilotRu остановлен.

Не копируйте вместе с профилем вслепую весь каталог `config/`: там находятся не только пользовательские профили, но и шаблоны, deploy-конфигурация, служебное состояние и другие файлы.

Для резервного копирования всего приложения используйте отдельные рекомендации из [Данные и резервные копии](../maintenance/data-backups.md).

## Чувствительные значения

Некоторые настройки специально помечены как sensitive. Например, `Error.OnePushConfig` содержит YAML конфигурации внешнего provider, а LLM-настройки могут содержать API key.

Не публикуйте профиль целиком в issue, чате или логе без проверки содержимого.

Если нужна помощь:

1. сделайте копию;
2. удалите/замаскируйте токены, пароли, ключи, приватные URL и идентификаторы;
3. приложите только минимально необходимый фрагмент.

## Импорт чужого профиля

Чужой профиль может содержать:

- другой serial устройства;
- другие боевые флоты;
- включённые задачи с уже наступившим `NextRun`;
- внешние уведомления;
- опасные для вашего аккаунта лимиты или автопокупки.

Поэтому импортированный профиль нельзя считать безопасным только потому, что JSON структурно корректен.

После импорта сначала проверьте устройство, планировщик, боевые задачи и чувствительные интеграции.

Далее: [Флоты и боевые настройки](fleets-and-combat.md).

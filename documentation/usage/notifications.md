# Уведомления

AzurPilotRu имеет несколько разных путей уведомлений. Они не являются одной общей кнопкой, поэтому важно различать **локальные уведомления WebUI**, **итоговые уведомления планировщика** и **внешний OnePush provider**.

## Локальный WebUI

Внутренние producer'ы могут отправлять уведомления в локальный WebUI.

Этот путь обращается к локальному endpoint WebUI на `127.0.0.1` и не требует внешнего provider.

Стандартный порт берётся из настроек WebUI, по умолчанию — `25548`.

## Scheduler.PushNotification

У задач существует флаг:

```text
Scheduler.PushNotification
```

Он включает итоговое уведомление планировщика там, где соответствующий producer его поддерживает.

По умолчанию общий шаблон задаёт:

```text
false
```

Это не то же самое, что настройка OnePush provider.

## Error.OnePushConfig

Основная внешняя provider-конфигурация хранится в:

```text
Error.OnePushConfig
```

Формат — YAML. Поле помечено как **sensitive**.

Значение по умолчанию:

```yaml
provider: null
```

При таком значении внешний канал не настроен.

Не публикуйте реальный `OnePushConfig`: в зависимости от provider он может содержать токен, ключ, адрес webhook или другие секреты.

## Operation Siren

У Operation Siren есть дополнительные настройки:

- `NotifyOpsiMail` — разрешение OnePush-уведомлений OpSi;
- `LauncherPush` — локальный launcher/WebUI-путь;
- `IndependentPush` — отдельная provider-конфигурация для Operation Siren;
- `OpsiOnePushConfig` — отдельный YAML provider, если `IndependentPush` включён.

Если отдельный provider отключён, OpSi может использовать общий `Error.OnePushConfig`.

Часть OpSi-уведомлений может быть шумной: текущая локализация прямо предупреждает о большом объёме сообщений для некоторых событий.

## Что может уходить во внешнюю сеть

Локальное уведомление WebUI остаётся локальным.

OnePush — внешний транспорт. Конкретные данные и endpoint зависят от выбранного provider. Поэтому включение внешних уведомлений является явным решением пользователя.

Перед настройкой:

1. определите, какой provider вы используете;
2. создайте отдельный токен с минимально необходимыми правами;
3. не храните конфигурацию в публичном месте;
4. проверьте первый тестовый push;
5. после публикации логов или профиля считайте случайно раскрытый токен скомпрометированным и перевыпустите его.

## Если уведомление не приходит

Проверьте по порядку:

- нужен ли именно локальный WebUI или внешний OnePush;
- включён ли producer события;
- включён ли `Scheduler.PushNotification`, если речь об итоговом scheduler-событии;
- не равен ли provider `null`;
- использует ли Operation Siren общий или независимый provider;
- доступен ли выбранный внешний сервис.

Не вставляйте секретный provider YAML в публичный issue при диагностике.

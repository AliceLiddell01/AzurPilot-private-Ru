# Первый запуск

После установки и подготовки Android runtime можно запустить WebUI.

## 1. Запустите Docker Desktop

Штатный Start проверяет локальную инфраструктуру проекта. Перед запуском убедитесь, что Docker Desktop полностью запущен и Docker Engine доступен.

## 2. Запустите AzurPilotRu

Обычный запуск:

```powershell
azur start
```

Запуск с автоматическим открытием браузера:

```powershell
azur start --browser
```

Перед созданием нового процесса Start:

- проверяет, что checkout подготовлен через Build;
- проверяет локальную инфраструктуру;
- проверяет состояние порта WebUI;
- не завершает чужой процесс только потому, что тот занял тот же порт;
- ожидает подтверждённой готовности WebUI.

Если WebUI уже запущен и его идентичность подтверждена, повторный Start не обязан создавать второй экземпляр.

## 3. Откройте WebUI

Стандартный локальный адрес:

```text
http://127.0.0.1:25548/
```

Если использован `azur start --browser`, страница откроется автоматически после подтверждения готовности.

WebUI персональной версии использует русский runtime-интерфейс `ru-RU`.

## 4. Проверьте базовую конфигурацию

До включения автоматизации убедитесь, что:

- выбран правильный пользовательский профиль;
- устройство или эмулятор соответствует тому, где запущена Azur Lane;
- package — Global;
- игра находится в нормальном рабочем состоянии;
- вы понимаете, какие задачи уже включены в выбранном профиле.

Не включайте сразу весь набор задач. На первом запуске важнее подтвердить стабильное подключение и понятный сценарий выполнения.

## 5. Как остановить AzurPilotRu

Штатная команда:

```powershell
azur stop
```

Закрытие вкладки браузера **не останавливает backend**.

Если `azur start` был запущен в foreground-режиме и именно это окно владеет процессом, `Ctrl+C` может завершить запущенный им WebUI. Но для обычного повседневного сценария используйте `azur stop`.

Повторный Stop безопасен: если подтверждённого процесса AzurPilotRu уже нет, команда не должна завершать случайный процесс, занявший тот же порт.

## Если запуск не удался

Сначала выполните:

```powershell
azur doctor
```

Если диагностика указывает на повреждённое окружение, переходите к [Диагностике и восстановлению](../maintenance/diagnostics-repair.md). Если проблема связана с Docker, ADB или портом WebUI, используйте [Решение проблем](../maintenance/troubleshooting.md).

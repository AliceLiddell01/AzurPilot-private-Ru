# Требования

Перед установкой AzurPilotRu подготовьте игру, Android-среду и инструменты, необходимые для первоначальной сборки.

## Поддерживаемая игровая версия

AzurPilotRu поддерживает только **Azur Lane Global/EN**.

Ожидаемые значения:

```text
server: en
package: com.YoStarEN.AzurLane
```

Если у вас установлена CN, JP, TW или другая региональная версия, текущий AzurPilotRu не следует считать совместимым с ней.

## Операционная система

Проект содержит кроссплатформенные компоненты, однако основной проверяемый пользовательский контур персональной версии — **Windows**.

На Windows проект дополнительно умеет:

- устанавливать проверенный ADB во внутреннее окружение проекта;
- регистрировать команду `azur` в пользовательском `PATH`;
- создавать пользовательский ярлык в меню «Пуск»;
- работать с проверенным Windows/MuMu/Global сценарием.

POSIX-код и отдельные Linux/macOS пути в проекте существуют, но эту документацию не следует воспринимать как обещание полного равенства всех платформ.

## Android-эмулятор или устройство

Нужен Android runtime, в котором установлена Azur Lane Global.

Для персональной версии основным проверяемым сценарием является **MuMu на Windows**. Унаследованный код содержит поддержку и других эмуляторов и методов подключения, но для первого знакомства рекомендуется начинать с проверенной конфигурации Windows + MuMu + Global.

Перед запуском AzurPilotRu:

- установите Azur Lane Global;
- войдите в игру;
- убедитесь, что игра запускается вручную;
- не закрывайте эмулятор перед первым подключением.

## Git

Текущая версия проекта не имеет готового установщика «в один клик». Репозиторий нужно получить локально, поэтому для стандартной установки требуется Git.

Рабочая пользовательская ветка:

```text
personal/stable
```

Ветка `master` сохраняется как зеркало исходного проекта и не является веткой персональной сборки.

## uv

Для первоначальной подготовки нужен внешний `uv`. Сам AzurPilotRu использует его как bootstrap-инструмент и затем создаёт собственное окружение `.venv`.

Текущий проект закрепляет `uv 0.12.15`; bootstrap проверяет совместимость найденного `uv` перед использованием.

Важно: отдельно устанавливать Python 3.14.6 вручную обычно не требуется только ради проектной `.venv`: bootstrap умеет запросить managed Python через `uv` и создать самоизолированное окружение. Формальный Python-контракт проекта при этом остаётся:

```text
>=3.14.6,<3.15
```

## Docker

Штатный `azur start` проверяет и поднимает локальную инфраструктуру проекта. Для основного Windows-сценария нужен работающий **Docker Desktop** с доступным Docker Engine/Compose.

В инфраструктуру входят, среди прочего:

- PostgreSQL — постоянное хранилище данных AzurPilotRu;
- Redis — восстанавливаемый runtime cache;
- сервисы observability;
- дополнительные операторские интерфейсы, если они настроены.

Не все эти сервисы требуют ручного использования, но Docker должен быть доступен приложению.

## Сеть и свободное место

Во время первого `azur build` могут загружаться:

- managed Python;
- Python-зависимости из lock-файла;
- ADB на Windows;
- Docker images при подготовке инфраструктуры.

Поэтому для первого запуска нужен доступ к сети и достаточное свободное место под `.venv`, кэш `uv`, Docker images и локальные данные.

## Минимальный контрольный список

Перед переходом к установке убедитесь, что:

- [ ] используется Azur Lane Global;
- [ ] игра запускается в MuMu или другом выбранном Android runtime;
- [ ] установлен Git;
- [ ] команда `uv --version` работает;
- [ ] Docker Desktop запущен;
- [ ] у пользователя есть место для локального checkout и Docker data.

Далее: [Установка](installation.md).

# Первая автоматизация

Первый успешный запуск автоматизации нужен не для того, чтобы сразу включить весь AzurPilotRu, а чтобы проверить цепочку:

**WebUI → профиль → планировщик → устройство → игра → завершение задачи → следующий запуск.**

## Выберите простой сценарий

Для первого теста не рекомендуется начинать с длительного фарма, сложной кампании, Операции «Сирена» или задач, которые могут много раз подряд расходовать игровые ресурсы.

Выберите знакомую вам регулярную задачу с понятным результатом — например, одну из задач порта или автосбора наград.

Даже «небоевая» автоматизация изменяет состояние игры, поэтому перед запуском проверьте её параметры.

## Как задачи попадают в планировщик

Во многих задачах есть пользовательский переключатель **«Включить эту функцию»**. Его смысл — добавить задачу в планировщик.

Есть исключения: интерфейс прямо указывает, что задачи комиссии, исследования и наград всегда включены в планировщик. Для таких задач важнее их собственная конфигурация и рассчитанное время следующего запуска.

У каждой планируемой задачи есть `NextRun` — время, когда она снова становится кандидатом на выполнение. Это не означает, что задача обязательно начнётся ровно в эту секунду: планировщик учитывает очередь и текущую активную работу.

## Рекомендуемый первый проход

1. Запустите AzurPilotRu через `azur start --browser`.
2. Откройте выбранный профиль.
3. Убедитесь, что устройство настроено правильно.
4. Откройте одну понятную задачу.
5. Проверьте её параметры и возможные расходы ресурсов.
6. Включите задачу, если у неё есть переключатель включения.
7. Сохраните/примените конфигурацию штатным способом WebUI.
8. Наблюдайте первый запуск и не оставляйте новую конфигурацию без присмотра.
9. После завершения проверьте журнал и время следующего запуска.

## Что должно происходить

Нормальная задача может:

- выполниться сразу;
- отложиться до `NextRun`;
- завершиться и передать управление другой готовой задаче;
- остановиться из-за собственного условия;
- запросить вмешательство пользователя при неоднозначном или небезопасном состоянии.

Отложенная задача не обязательно является ошибкой. Например, некоторые действия естественно зависят от игровых таймеров.

## Когда остановить тест

Остановите AzurPilotRu через `azur stop`, если:

- программа взаимодействует не с тем устройством;
- открывает неожиданный раздел игры;
- начинает расходовать ресурс, который вы не собирались тратить;
- многократно повторяет действие без понятного прогресса;
- интерфейс или журнал сообщает о необходимости ручного вмешательства.

Не пытайтесь исправлять непонятное поведение включением дополнительных задач.

После первой успешной автоматизации переходите к [WebUI](../usage/webui.md) и [Планировщику](../usage/scheduler.md), а затем настраивайте нужные разделы из [Задач автоматизации](../automation/README.md).

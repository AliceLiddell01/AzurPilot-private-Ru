# Установка

Текущий AzurPilotRu устанавливается из Git-репозитория. Отдельного готового установщика «в один клик» пока нет.

Ниже описан базовый Windows-сценарий для ветки `personal/stable`.

## 1. Получите репозиторий

Откройте PowerShell и клонируйте пользовательскую стабильную ветку:

```powershell
git clone --branch personal/stable --single-branch https://github.com/AliceLiddell01/AzurPilot-private-Ru.git
Set-Location .\AzurPilot-private-Ru
```

После этого текущий каталог должен быть корнем проекта и содержать, среди прочего, `pyproject.toml`, `uv.lock`, `azurpilot` и `config`.

> **Не используйте `master` как пользовательскую установку.** В этом репозитории `master` предназначен для зеркала исходного проекта, а персональная версия живёт в `personal/stable`.

## 2. Подготовьте окружение

Пока команда `azur` ещё не установлена, первый Build запускается через внешний `uv`:

```powershell
uv --project . run --locked python -m azurpilot build
```

`build` выполняет подготовку checkout без Git update. В частности, он:

- создаёт или проверяет проектное окружение `.venv`;
- использует locked-зависимости проекта;
- подготавливает managed Python требуемой версии;
- на Windows проверяет и при необходимости устанавливает проектный ADB;
- регистрирует каталог команды `azur` в пользовательском `PATH`;
- по умолчанию создаёт или проверяет ярлык Windows.

Build не должен использоваться как замена `azur update`: он не обновляет исходный код из Git.

## 3. Откройте новый терминал

После успешного Build закройте текущее окно PowerShell и откройте новое.

Это важно, потому что уже открытая оболочка не получает изменения пользовательского `PATH` задним числом.

Проверьте, что команда стала доступна:

```powershell
azur doctor
```

`doctor` выполняет read-only проверку возможностей проекта и не должен исправлять состояние автоматически.

## 4. Что считать успешной установкой

Базовая подготовка считается завершённой, если:

- `azur doctor` запускается;
- проектный Python и `uv` распознаются как исправные;
- на Windows ADB либо готов, либо диагностика явно объясняет его состояние;
- checkout однозначно определяется как AzurPilotRu;
- Docker доступен для последующего запуска инфраструктуры.

Предупреждение не всегда означает, что установка полностью сломана. Например, необязательная возможность может иметь статус «не настроено». Ориентируйтесь на итоговый код и текст `doctor`.

## Если Build завершился ошибкой

Не удаляйте `.venv`, transaction-каталоги или другие служебные данные наугад.

Сначала повторно получите диагностику:

```powershell
azur doctor
```

Если команда `azur` ещё не зарегистрировалась, используйте прямой запуск из checkout:

```powershell
uv --project . run --locked python -m azurpilot doctor
```

После успешной установки переходите к [Подключению Azur Lane](device-connection.md).
